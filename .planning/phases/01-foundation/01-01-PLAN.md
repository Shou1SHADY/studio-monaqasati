# 01-01-PLAN.md - Phase 1 Foundation

## Goal
Establish the architectural foundation for organization-based data access.

## Tasks
1. **Schema Update Strategy**
   - Define the `User` interface update in a shared types file or directly in the provider.
   - Plan the migration for existing users, RFQs, and Offers.

2. **Firebase Provider Update**
   - Modify `useUser()` or `useFirebase()` in `src/firebase/provider.tsx` to include `organizationId` and `organizationRole` in the profile data.
   - Ensure these fields are fetched from the `users` collection upon login.

3. **Migration Script**
   - Create a one-time utility script (`scripts/migrate-to-orgs.ts`) to:
     - Set `organizationId = uid` for all users.
     - Set `organizationRole = 'owner'` for all users.
     - Update all existing RFQs to include `organizationId` (matching the `contractorId`).
     - Update all existing Offers to include `organizationId` (matching the `supplierId`).

4. **Security Rules Update**
   - Update `firestore.rules` to allow access to RFQs/Offers if the user's `organizationId` matches the document's `organizationId`.

## Verification Criteria
- [ ] Users have `organizationId` in their Firestore document.
- [ ] The `useFirebase()` hook returns the correct `organizationId`.
- [ ] Existing RFQs/Offers are correctly linked to their creator's organization.
- [ ] Firestore rules pass validation (if tests exist).
