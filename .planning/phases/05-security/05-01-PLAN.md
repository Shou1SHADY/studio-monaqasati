# 05-01-PLAN.md - Phase 5 Google Auth & Security Advanced

## Goal
Secure user access by integrating Google Authentication, Email Verification, and custom 2-Step Verification (MFA) via SMS OTP using Firebase Auth and Firestore.

## Tasks

### 1. Google Authentication Integration
- **Login Page (`src/app/login/page.tsx`)**:
  - Add a premium "Sign in with Google" button.
  - Implement Firebase `GoogleAuthProvider` and `signInWithPopup`.
  - On login, check if a Firestore document exists in `/users/{uid}`.
  - If it exists, retrieve the user's role and redirect them to their dashboard.
  - If it does not exist, check for an invitation, redirect to `/register` with their Google details (email, name) pre-filled, and show a helpful Toast: "يرجى إكمال بيانات التسجيل لإنشاء حسابك".
- **Register Page (`src/app/register/page.tsx`)**:
  - Add a premium "Sign up with Google" button.
  - Validate that the user has selected their role and filled in other required organization details (CR Number, Phone, Tax, Specializations, etc.) before calling Google sign-up.
  - Once validated, authenticate with Google, create their user document in Firestore under their Google `uid`, accept any active invitations, and redirect them to their portal.

### 2. Email Verification Gate
- **Registration Flow**:
  - Automatically call `sendEmailVerification(user)` after standard email/password registration.
- **Verification Page (`src/app/verify-email/page.tsx`)**:
  - Create a stunning, user-friendly page with glassmorphism design.
  - Show status of verification, button to re-send verification link, button to check verification status (`user.reload()`), and a button to logout.
- **Portal Guard (`src/components/layout/portal-layout.tsx`)**:
  - If the user is logged in, has provider `password`, and is not verified (`!user.emailVerified`), redirect them to `/verify-email`.

### 3. 2-Step Verification (MFA) via SMS OTP
- **Profile Tab (`src/app/(supplier)/supplier/profile/page.tsx` and `src/app/(contractor)/contractor/profile/page.tsx`)**:
  - Create a new "Security" (الأمان) tab containing a switch to toggle Two-Step Verification.
  - Saving the toggle status (`twoFactorEnabled: true/false`) to their Firestore user document.
- **Verification Flow**:
  - Update standard login to check if `profile.twoFactorEnabled === true`.
  - If enabled, generate a 6-digit random code, save it in a Firestore subcollection under `/users/{uid}/2fa/current` with an expiration timestamp, and send it to their phone via `/api/sms` (using Twilio).
  - Keep them on a beautiful 2FA verification screen/dialog until they enter the correct 6-digit code.
  - Store the verification success state in `sessionStorage` (e.g. `2fa_verified_{uid}: true`) upon successful code match.
  - Update `PortalLayout` to verify that if `profile.twoFactorEnabled` is true, they have completed the challenge (`2fa_verified` exists in sessionStorage). If not, redirect them to the challenge page or `/login` with 2FA active.

## Verification Criteria
- [x] Users can sign up and sign in using Google.
- [x] Registering with email/password sends a verification email.
- [x] Access is blocked if the email is not verified, showing a stunning `/verify-email` gate.
- [x] Enabling 2-Step Verification toggles the Firestore state and triggers a 6-digit SMS OTP upon logging in.
- [x] Entering the correct OTP logs the user in, while incorrect/expired codes are rejected.
