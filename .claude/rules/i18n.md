# i18n Rules — next-intl (ar/en)

## Key Principle

**Every user-visible string MUST be in `messages/ar.json` AND `messages/en.json`.**

Never hardcode Arabic or English strings in components.

## Usage Pattern

```tsx
// Server Component
import { getTranslations } from 'next-intl/server';
const t = await getTranslations('Namespace');

// Client Component
import { useTranslations } from 'next-intl';
const t = useTranslations('Namespace');

// Usage
<h1>{t('title')}</h1>
<p>{t('description', { name: userName })}</p>
```

## Navigation

```tsx
// ALWAYS use this Link — NOT next/link
import { Link } from '@/i18n/routing';

// For programmatic navigation
import { useRouter } from '@/i18n/routing';
```

## Locale Detection

```tsx
// In Server Components
const { locale } = await params; // from page props

// In Client Components
import { useLocale } from 'next-intl';
const locale = useLocale();

// Direction
const isRTL = locale === 'ar';
const dir = isRTL ? 'rtl' : 'ltr';
```

## Translation File Structure

Keep namespaces flat and consistent between ar.json and en.json:
```json
{
  "Namespace": {
    "title": "...",
    "description": "...",
    "actions": {
      "submit": "...",
      "cancel": "..."
    }
  }
}
```

## Arabic-Specific Rules

1. **Line height** ≥ 1.6 on all Arabic headings (enforced in globals.css)
2. **NO letter-spacing** on Arabic text — breaks cursive connections
3. **Numbers**: Arabic locale uses Eastern Arabic numerals by default — handle gracefully
4. **Date formatting**: use `date-fns` with locale-aware formatting
5. **Pluralization**: Arabic has 6 plural forms — use next-intl plural rules properly

## Route Structure

- Default locale (Arabic): `/` — no prefix (localePrefix: 'as-needed')
- English: `/en/*`
- Locale detection is DISABLED — Arabic is always default
